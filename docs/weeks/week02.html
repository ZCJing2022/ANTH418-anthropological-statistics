Overview

This week is about learning a workflow, not memorizing commands.

R is the language we will use to work with data. RStudio is the environment in which we will organize and run that work. Quarto is the document system that brings prose, R code, results, tables, figures, and citations together in a reproducible report (Tierney 2025).

By the end of the week, you should be able to open an RStudio project, understand the basic structure of an R command, create and inspect R objects, import a CSV file, use a small set of tidyverse verbs, create a first ggplot2 figure, and render a Quarto document from a clean R session.

NoteThe Week 2 principle

Do not separate “doing the analysis” from “documenting the analysis.”

In ANTH418, the code that produces a result should live beside the explanation of what the result means.

Questions

  • What are R, RStudio, and Quarto, and how do they differ?
  • What is an R object, vector, function, data frame, or package?
  • How should files be organized so that code can find them reliably?
  • How do we import and inspect a real archaeological dataset?
  • What do select(), filter(), mutate(), summarise(), group_by(), and |> do?
  • How does a Quarto document turn code and prose into a reproducible HTML page?
  • What does one row in the Knipper teaching dataset represent?

Learning objectives

By the end of Week 2, you should be able to:

  1. distinguish R, RStudio, and Quarto;
  2. use an RStudio Project and project-relative file paths rather than machine-specific paths;
  3. create and inspect basic R objects, vectors, and data frames;
  4. recognize common data types, including numeric, character, logical, and missing (NA) values;
  5. explain the basic syntax of an R function and use R’s help system;
  6. import a CSV file with read_csv() and inspect it with glimpse(), names(), and dim();
  7. use the native R pipe |> to build readable sequences of data operations;
  8. use introductory dplyr verbs to select, filter, transform, group, and summarize data;
  9. construct a simple ggplot2 visualization;
  10. create named Quarto code cells, use basic #| cell options, and render a .qmd file; and
  11. re-render a document from a clean R session.

Before class: install the software

ANTH418 assumes no previous programming experience. Before beginning the exercises below, make sure that R and RStudio are installed and working on your computer.

The three names can be confusing at first:

R is the language that performs the computation.
RStudio is the application in which we will write and organize most of our R work.
Quarto turns our code, results, figures, and writing into a reproducible document.

Step 1 — Install R

Download R from the Comprehensive R Archive Network (CRAN):

https://cran.r-project.org/

Choose the installer for your operating system:

  • macOS: choose Download R for macOS and install the current release appropriate for your Mac;
  • Windows: choose Download R for Windows → base → the current release; or
  • Linux: follow the instructions for your distribution.

Use the standard/default installation options unless you have a specific reason to change them.

NoteR must be installed before RStudio

RStudio does not replace R. It provides an easier environment for working with R, but it still needs an R installation on your computer.

Step 2 — Install RStudio Desktop

Download the free RStudio Desktop from Posit:

https://posit.co/download/rstudio-desktop/

Install the current stable release for your operating system.

On first launch, RStudio should normally find your R installation automatically.

Current versions of RStudio include integrated support for Quarto and bundle a stable Quarto release. For most ANTH418 students, installing current R and current RStudio is therefore enough to begin working with .qmd files.

Step 3 — Check Quarto

After installing RStudio, open it and choose the Terminal tab. Run:

quarto --version

You should see a version number.

Then run:

quarto check

This checks whether Quarto can find the software it needs, including R and the Knitr execution engine.

TipDo I need to install Quarto separately?

Usually no if you have installed a current release of RStudio, because RStudio bundles Quarto.

If quarto --version does not work, or if you need a newer standalone Quarto release, install it from:

https://quarto.org/docs/get-started/

After installation, restart RStudio and run quarto --version again.

Step 4 — Install the R packages used in ANTH418

Packages extend what R can do. For the first part of the course, the main package collection we need is the tidyverse.

In the R Console, run:

install.packages("tidyverse")

You normally install a package only once on a computer.

Then test that it loads:

library(tidyverse)

If the command finishes without an error, the package is available.

ImportantConsole or Terminal?

RStudio contains both, but they serve different purposes.

  • Use the R Console for R commands such as install.packages() and library().
  • Use the Terminal for system commands such as quarto --version and quarto check.

We will use both during the course.

Step 5 — Verify the complete setup

In the R Console, run:

R.version.string
1 + 1
library(tidyverse)

You should see your R version, the result 2, and no error when the tidyverse loads.

In the Terminal, run:

quarto --version

If those checks work, you have the basic ANTH418 computational environment.

In RStudio choose:

File → New File → Quarto Document…

R, RStudio, and Quarto

R

R is a programming language and statistical computing environment.

When you write

mean(c(4, 7, 9))

R evaluates the instruction and returns a result.

R is where the computation happens.

RStudio

RStudio is an integrated development environment (IDE). It gives you a convenient place to work with R:

  • the Source pane for scripts and Quarto documents;
  • the Console for commands and output;
  • the Environment pane for objects currently in memory;
  • the Files / Plots / Packages / Help panes for navigating the project and inspecting results; and
  • project tools that help keep files, code, and working directories organized.

An RStudio Project is especially important because it gives a project a stable root directory. Project-based organization prevents many file-path problems and makes analyses more portable (Tierney 2025).

Quarto

Quarto is a scientific and technical publishing system.

A Quarto document can contain:

  • Markdown prose;
  • executable R code;
  • tables;
  • figures;
  • equations;
  • citations; and
  • cross-references.

The .qmd source is the document you edit. Rendering turns it into an output such as HTML, PDF, or Word.

TipA useful mental model

R computes. RStudio organizes. Quarto communicates reproducibly.

Projects and file paths

A reproducible analysis should not depend on a path that only exists on your own computer.

Avoid code such as:

# Do not write paths like this in course work:
read_csv("/Users/yourname/Desktop/my-course/data/file.csv")

and avoid beginning an analysis with:

setwd("/Users/yourname/some/very/specific/location")

Instead, open the relevant RStudio Project and work with relative paths:

read_csv("data/file.csv")

This is one of the workflow practices emphasized in Quarto for Scientists: keep the files for one project together and let the project establish a stable starting point for your analysis (Tierney 2025).

Inspect your current project

Run these commands in the Console:

getwd()
list.files()
file.exists("data")

Vectors and data types

A vector contains multiple values of the same basic type. Thulin introduces vectors and data frames as fundamental structures for storing observations in R (Thulin 2025).

sites <- c("La Bastida", "Gatas")
sample_sizes <- c(48, 21)
include_site <- c(TRUE, TRUE)

[1] TRUE TRUE

Useful questions about an object include:

length(sample_sizes)
[1] 2
class(sample_sizes)
[1] "numeric"
class(sites)
[1] "character"
class(include_site)
[1] "logical"

Common types you will encounter include:

R type Example Typical anthropological use
numeric 11.52 isotope value, age, length, count represented numerically
character "Gatas" site name, category label, specimen code
logical TRUE yes/no or inclusion flags
missing NA value not recorded or not known
WarningNA is not zero

NA means a value is missing. A recorded value of 0 is an observed value.

This distinction will become a major analytical issue in Week 6.

Functions

A function is a reusable set of instructions. A function usually takes one or more inputs—called arguments—and returns a result. This function-centered way of working is fundamental to R (Perkins 2026; Thulin 2025).

isotope_values <- c(10.2, 11.4, 9.8, 12.1)

mean(isotope_values)
[1] 10.875
min(isotope_values)
[1] 9.8
max(isotope_values)
[1] 12.1
length(isotope_values)
[1] 4

The basic pattern is:

function_name(argument)

Functions can have additional arguments:

values_with_missing <- c(10.2, 11.4, NA, 12.1)

mean(values_with_missing)
[1] NA
mean(values_with_missing, na.rm = TRUE)
[1] 11.23333

Ask R for help

Use ? or help():

?mean
help(mean)
?read_csv
TipDo not try to memorize every function

Professional R users repeatedly consult documentation. The goal is to understand what you want to do, recognize the relevant function, read its arguments, and verify its behavior.

Packages and the tidyverse

R includes many functions by default. Additional functions are distributed in packages.

For this course, we will use a deliberately small set of packages. The most common will come from the tidyverse, including:

  • readr for importing rectangular data;
  • dplyr for data manipulation;
  • tidyr for reshaping data;
  • ggplot2 for visualization;
  • stringr for text; and
  • forcats for categorical variables.
NoteInstall once; load each session

You normally install a package once:

install.packages("tidyverse")

Then load it in each new R session or reproducible document:

library(tidyverse)

Do not put install.packages() inside a submitted analytical workflow.

The pipe: |>

The native R pipe |> passes the result of one step into the next step.

Without a pipe:

round(mean(c(10.2, 11.4, 9.8, 12.1)), 2)
[1] 10.88

With intermediate objects:

x <- c(10.2, 11.4, 9.8, 12.1)
x_mean <- mean(x)
round(x_mean, 2)
[1] 10.88

With a pipe:

c(10.2, 11.4, 9.8, 12.1) |>
  mean() |>
  round(2)
[1] 10.88

For data analysis, pipes are especially useful because they allow us to read the code from top to bottom as a sequence of operations.

Core dplyr verbs

We will repeatedly use a small vocabulary of data verbs.

Verb Main question
select() Which columns do I need?
filter() Which rows do I need?
mutate() What new or transformed variable do I need?
arrange() In what order should the rows appear?
group_by() Which observations should be treated as groups?
summarise() What summary should I calculate?
count() How many observations occur in each category?

Here is a small example:

toy_data |>
  filter(site == "La Bastida") |>
  select(individual, d15n)
# A tibble: 2 × 2
  individual  d15n
  <chr>      <dbl>
1 A           10.4
2 B           11.7

And a transformation:

toy_data |>

Quarto: prose and computation in one document

A Quarto document has three important ingredients:

  1. YAML metadata at the top;
  2. Markdown prose; and
  3. executable code cells.

A minimal document looks like this:

---
title: "My first Quarto report"
format: html
---

## Question

What does the dataset show?


::: {.cell}

```{.r .cell-code}
1 + 1
```

::: {.cell-output .cell-output-stdout}

```
[1] 2
```


:::
:::

Quarto code-cell options begin with #|. Quarto for Scientists highlights options such as eval, echo, and include, which control whether code runs and whether code or output appears in the rendered document (Tierney 2025).

For example:


::: {.cell}

```{.r .cell-code}
mean(my_data)
```
:::

Three useful code-cell options

Option Meaning
eval: false show the code but do not run it
echo: false run the code but hide the source code
include: false run the code but hide both code and visible output

In ANTH418, important analytical code will usually remain visible because understanding the code is part of the course.

A few shortcuts save a great deal of time.

Case study: your first archaeological dataset

Bronze Age La Bastida and Gatas

The practice dataset comes from the stable-isotope research reported by Knipper and colleagues on Early Bronze Age La Bastida and Gatas in southeast Iberia (Knipper et al. 2020).

The published study uses stable carbon and nitrogen isotope evidence to investigate diet, farming, animal management, and food webs. For Week 2, however, our goal is much narrower:

Can we import, inspect, filter, summarize, and visualize the human isotope teaching data correctly?

We are not yet trying to complete the descriptive analysis required in Assignment 1.

NoteWhy does our teaching file have 69 individuals?

The published study describes an overall human sample of 75 individuals, but the reported human isotope results contain 48 individuals from La Bastida and 21 from Gatas, for 69 analyzed human observations (Knipper et al. 2020).

The validated ANTH418 teaching file follows those 69 analyzed observations. Do not infer the reason for the difference between the overall sample and analyzed isotope observations without checking the publication and supporting information.

Reading R code as a sequence of questions

Consider:

knipper |>
  filter(site == "Gatas") |>
  select(grave_no, d13c, d15n) |>
  arrange(d15n)

Read it as a sequence:

  1. Start with the human isotope dataset.
  2. Keep only Gatas.
  3. Keep only grave number and the two isotope variables.
  4. Order the observations by d15n.

This is more useful than memorizing individual commands because the code mirrors the analytical decisions.

Common errors and how to read them

Learning R includes learning to read errors.

object 'x' not found

R cannot find an object with that name.

Check:

  • Did you create it?
  • Did you run the code cell that creates it?
  • Is the spelling identical?
  • Did you restart R without recreating the object?

cannot open the connection or No such file or directory

R cannot find a file at the path you supplied.

Check:

getwd()
file.exists("data/your_file.csv")

Then inspect the path rather than immediately using setwd().

could not find function

The function may belong to a package that has not been loaded.

For example:

library(tidyverse)

or use the explicit form:

readr::read_csv("data/file.csv")

The Console shows + instead of >

R thinks your command is incomplete—often because of a missing parenthesis, quotation mark, or bracket. Thulin uses this as an example of how R signals an unfinished expression (Thulin 2025).

Press Esc to cancel, then inspect the command.

Rendering is the reproducibility test

Running code interactively is not enough.

A Quarto document should be able to rebuild its results in the correct order from the code written in the document.

At the end of your work:

  1. save the .qmd file;
  2. restart R;
  3. do not manually recreate objects in the Console;
  4. render the document; and
  5. fix any errors revealed by the clean render.
ImportantA document that only works because of objects left in your Environment is not reproducible

Rendering from a clean session exposes hidden dependencies and missing steps.

This habit will become increasingly important as ANTH418 analyses become more complex.

Quarto feature: inline R

Quarto can place a computed value directly into prose.

For example, after importing the dataset, this source:

The teaching dataset contains 69 observations.

renders as:

The teaching dataset contains 69 observations.

If the underlying dataset changes, the prose changes when the document is rendered. This helps prevent contradictions between text and computed results.

Reading guide

Required: Perkins

Perkins’s Using R for Introductory Statistics in Social Sciences is designed as a beginner-facing introduction to R for social-science analysis (Perkins 2026). For Week 2, concentrate on Chapter 2, “Welcome to the R Environment” (pp. 3–17).

While reading, make sure you can answer:

  • What is the role of the R environment?
  • How do you enter and execute commands?
  • What is an object?
  • How are functions used?
  • How should a beginner interpret R output and errors?

You do not need to memorize commands. Re-run examples and change them.

Required: Thulin

Thulin’s Modern Statistics with R develops R from basic objects and functions into data wrangling and programming (Thulin 2025).

For Week 2, use the assigned chapters selectively:

  • Chapter 1, Introduction (pp. 1–3): understand the broader statistical-computing workflow.
  • Chapter 2, The Basics (pp. 4–57): prioritize objects, vectors, data frames, functions, indexing, importing data, and basic operations.
  • Chapter 5, Dealing with Messy Data (pp. 158–211): focus this week on data types and the sections introducing dplyr/tidyr, filtering, selecting, and chained operations. Do not try to memorize every data-cleaning recipe.
  • Chapter 6, R Programming (pp. 212–247): read for programming habits and the logic of reusable code. Iteration and more advanced programming will become more meaningful later in the course.

Thulin’s online edition emphasizes that real data are often messy and that modern R work combines importing, filtering, reshaping, visualization, inference, and programming rather than treating these as separate activities (Thulin 2025).

Takeaways

  • R: data analysis is built from objects, functions, and explicit operations.
  • RStudio: project-based organization makes analytical work easier to manage and reproduce.
