Week 5 — Exploratory Data Analysis and Visualization

Looking directly at data before formal inference

Published

October 5, 2026

Class meetings: 5 & 7 October 2026
Focus: exploratory data analysis · visualization · ggplot2 · comparison · non-independence
Case study: Kinbank global kinship terminology data
Assessment: Assignment 2 — Visualizing Kinship Diversity with Kinbank

NoteThe Week 5 principle

Look first. Visualize deliberately. Infer carefully.

Use graphics to expose empirical structure and the structure of the evidence before trying to explain why a pattern exists.

Why This Week Matters

Exploratory data analysis (EDA) is how we learn what a dataset actually contains before formal inference. The goal is not simply to make attractive graphs. It is to inspect the evidence, choose displays that match variables and questions, compare patterns deliberately, identify problems, and generate better questions.

Week 5 workflow: inspect → describe → visualize → compare → question → revise → investigate

The revised Assignment 2 applies this workflow to Kinbank: visualize sample structure, examine kin_term_count, make a purposeful group comparison, and consider how shared ancestry or geography complicate interpretation.

TipPractice dataset

The examples in this Study Guide use the same frozen Kinbank teaching dataset as Assignment 2. Each row represents one language. You can run and modify the examples directly while working through the guide.

1. What You Should Understand

By the end of Week 5, you should be able to:

  1. explain EDA as an iterative mode of inquiry;
  2. distinguish description from inference;
  3. choose graphics from variable type and analytical purpose;
  4. create and interpret bar charts, histograms, boxplots, scatterplots, and facets;
  5. explain what a graphic preserves and hides;
  6. explain the ggplot2 grammar: data, mappings, layers, geoms, stats, positions, scales, coordinates, facets, and themes;
  7. distinguish mapping inside aes() from setting outside aes();
  8. combine raw observations and summaries with layers;
  9. recognize misleading graphical choices;
  10. visualize sample structure before substantive patterns; and
  11. recognize phylogenetic and spatial non-independence.

2. EDA: Description Before Inference

Ask: What is the observational unit? Which variables are categorical or numerical? What is missing? Are group sizes balanced? What does each distribution look like? Are there unusual observations? Does a pattern change across groups? Are observations independent?

Descriptive: “In this sample, kin_term_count is right-skewed.”

Inferential: “Languages in this region generally have more complex kinship systems.”

The second requires additional evidence and an appropriate inferential design. During EDA use language such as “in this sample,” “the graph suggests,” and “worth investigating.”

3. Match Graphics to Variables

Question Variables Useful first display
How common is each category? categorical bar chart
What is the distribution? numerical histogram
What are center, spread, and unusual values? numerical boxplot
How do distributions differ among groups? numerical + categorical boxplot + points; facets
Are two numerical variables associated? numerical + numerical scatterplot
Does a pattern vary by group? variables + group aesthetics or facets

Choose the graphic from the variable combination and analytical task, not from habit.

4. The Basic ggplot2 Pattern

Every basic ggplot2 graphic needs data, aesthetic mappings, and at least one layer:

ggplot(data = dat,
       mapping = aes(x = kin_term_count)) +
  geom_histogram()

Read this as: use dat; map kin_term_count to x; represent the distribution with a histogram layer.

5. Mapping Versus Setting

Map a variable:

geom_point(aes(colour = macroarea))

Set a constant:

geom_point(colour = "steelblue")

A common mistake:

geom_point(aes(colour = "steelblue"))

Variable inside aes(); fixed appearance outside aes().

6. Practice 1 — Build a Plot Layer by Layer

ggplot(dat)
ggplot(dat, aes(x = kin_term_count))
ggplot(dat, aes(x = kin_term_count)) +
  geom_histogram(binwidth = 25)
ggplot(dat, aes(x = kin_term_count)) +
  geom_histogram(binwidth = 25) +
  labs(
    x = "Kinbank form records linked to language",
    y = "Number of languages",
    title = "Distribution of kin_term_count"
  ) +
  theme_minimal()

The data and mapping remain stable while graphical components are added with +.

6. Practice 1A — Read the Anatomy of ggplot2 Code

Before writing more plots, practice reading a ggplot specification. Consider:

ggplot(
  data = dat,
  mapping = aes(x = macroarea, y = kin_term_count)
) +
  geom_boxplot(fill = "white") +
  geom_jitter(
    aes(colour = macroarea),
    width = 0.15,
    alpha = 0.25
  ) +
  labs(
    x = "Macroarea",
    y = "Kinbank form records linked to language"
  ) +
  theme_minimal()

Identify each component before running the code:

Component Where is it? What does it do?
Data data = dat supplies the observations and variables
Global mapping aes(x = macroarea, y = kin_term_count) maps variables to x and y for layers that inherit it
First geom geom_boxplot() adds a distribution summary
Fixed setting fill = "white" gives every box the same fill
Second geom geom_jitter() adds individual observations
Local mapping aes(colour = macroarea) maps colour only in the jitter layer
Fixed settings width = 0.15, alpha = 0.25 control jitter and transparency without encoding variables
Labels labs() supplies human-readable labels
Theme theme_minimal() changes non-data appearance

Try it yourself

For each line below, decide whether it is data, mapping, geom, fixed setting, label, or theme:

aes(x = kin_term_count)
geom_histogram(binwidth = 25)
fill = "steelblue"
aes(colour = family)
labs(x = "Kin-term count")
theme_minimal()

Then answer:

  1. Why is binwidth = 25 outside aes()?
  2. Why is colour = family inside aes() when colour should represent language family?
  3. Which parts change the meaning of the data encoding, and which parts mainly change presentation?

The goal is to read ggplot2 code as a graphical specification, not as a string of commands to memorize.

7. Geoms and Stats

Geom Typical stat Operation
geom_point() identity raw observations
geom_bar() count count categories
geom_histogram() bin bin values, then count
geom_boxplot() boxplot quartiles and IQR summaries

A histogram performs raw values → bins → counts → bars. A geom is one component of a graphic, not the whole graphic.

8. Practice 2 — Bar Charts and Sample Structure

macro_counts <- dat |>
  filter(!is.na(macroarea)) |>
  count(macroarea, sort = TRUE)

Plot precomputed counts:

ggplot(macro_counts,
       aes(x = reorder(macroarea, n), y = n)) +
  geom_col() +
  coord_flip() +
  labs(x = NULL, y = "Number of languages") +
  theme_minimal()

Or count raw rows automatically:

ggplot(dat |> filter(!is.na(macroarea)),
       aes(x = macroarea)) +
  geom_bar()

geom_bar() counts observations; geom_col() uses supplied heights. Ask what unequal representation tells you about the structure of the evidence.

9. Practice 3 — Histograms and Bin Width

Compare:

ggplot(dat, aes(x = kin_term_count)) +
  geom_histogram(binwidth = 10)
ggplot(dat, aes(x = kin_term_count)) +
  geom_histogram(binwidth = 25)
ggplot(dat, aes(x = kin_term_count)) +
  geom_histogram(binwidth = 50)

Which features persist? Which change? Too few bins can hide structure; too many can make noise look important.

10. Practice 4 — Boxplot Plus Raw Observations

ggplot(dat |> filter(!is.na(macroarea)),
       aes(x = macroarea, y = kin_term_count)) +
  geom_boxplot(outlier.shape = NA) +
  geom_jitter(width = 0.15, alpha = 0.2)

For readability:

ggplot(dat |> filter(!is.na(macroarea)),
       aes(x = reorder(macroarea, kin_term_count, FUN = median),
           y = kin_term_count)) +
  geom_boxplot(outlier.shape = NA) +
  geom_jitter(width = 0.15, alpha = 0.2) +
  coord_flip()

The boxplot summarizes; points reveal observations, overlap, extreme values, and unequal group sizes.

11. Faceting and Small Multiples

ggplot(dat |> filter(!is.na(macroarea)),
       aes(x = kin_term_count)) +
  geom_histogram(binwidth = 25) +
  facet_wrap(~ macroarea)

Fixed scales support between-panel comparison:

facet_wrap(~ macroarea, scales = "fixed")

Free scales reveal within-panel detail but weaken direct magnitude comparison:

facet_wrap(~ macroarea, scales = "free")

For Assignment 2, fixed scales are usually the better starting point when direct comparison is the goal.

12. Practice 5 — Aesthetic or Facet?

Colour by group:

ggplot(dat |> filter(!is.na(macroarea)),
       aes(x = longitude, y = latitude, colour = macroarea)) +
  geom_point(alpha = 0.6)

Or facet:

ggplot(dat |> filter(!is.na(macroarea)),
       aes(x = longitude, y = latitude)) +
  geom_point(alpha = 0.6) +
  facet_wrap(~ macroarea)

Ask which design better supports the intended comparison. The grammar supplies alternatives; statistical reasoning determines which is useful.

13. Scales, Guides, Coordinates, and Themes

A scale maps data values to visual values. Mapping macroarea to colour creates a discrete colour scale; mapping kin_term_count to x creates a numerical position scale.

Scales also generate guides: position scales generate axes; colour, shape, and size scales generally generate legends. Both help readers translate visual properties back into data values.

A coordinate system determines how positions are placed. coord_flip() can make categorical labels easier to read.

A theme controls non-data appearance. theme_minimal() changes styling, not the meaning of variables.

14. Layers and Local Mappings

ggplot(dat, aes(x = macroarea, y = kin_term_count)) +
  geom_boxplot(outlier.shape = NA) +
  geom_jitter(width = 0.15, alpha = 0.2)

Both layers inherit global mappings.

A local mapping applies only to one layer:

ggplot(dat, aes(x = longitude, y = latitude)) +
  geom_point(aes(colour = macroarea), alpha = 0.5)

15. Visual Channels Should Match the Task

For quantitative magnitude, position on a common scale is especially effective; length can also work well. For categorical identity, useful channels include colour hue, shape for a few groups, spatial separation, and facets.

Do not use unrelated hues as though they represented numerical order. Use colour to carry information rather than decoration. Consider redundant encoding such as colour plus shape when accessibility matters.

16. Practice 6 — Debug Common ggplot2 Mistakes

Fixed colour accidentally mapped:

# Wrong
geom_point(aes(colour = "blue"))

# Correct
geom_point(colour = "blue")

Missing mapping:

ggplot(dat) +
  geom_histogram()

What variable should be on x?

If a table already contains n, use geom_col(aes(y = n)) rather than asking geom_bar() to count rows again.

Avoid unnecessary combinations of colour + shape + size + alpha. Valid code is not necessarily useful EDA: state the comparison your graph is designed to support.

17. Visualization Can Mislead

Watch for truncated axes, overplotting, unequal group sizes, proportions without denominators, excessive colour, free facet scales used carelessly, smoothers treated as truth, and outliers automatically treated as errors.

Ask:

What is being counted? How many cases support the comparison? What has the display hidden?

18. Kinbank: Visualize the Evidence First

The teaching dataset contains 1,287 languages represented by at least one Kinbank form record. kin_term_count counts form records linked to a language in the frozen teaching snapshot. It is not automatically the number of unique kin concepts and is not a direct measure of kinship-system complexity.

Before interpreting group differences, examine family representation, macroarea representation, missing metadata, geographical coverage, and unequal group sizes.

Sample composition is part of the evidence.

19. Kinship Diversity Depends on Operationalization

Kinbank maps culturally specific terminology onto an etic genealogical framework. A single variable such as kin_term_count compresses a relational system. Two languages can have similar counts while organizing kin relations differently.

A visualization is only as interpretable as the variable it represents.

20. Cross-Cultural Non-Independence

Languages are not automatically independent observations.

Phylogenetic autocorrelation: shared ancestry, common descent, inherited terminology.

Spatial autocorrelation: borrowing/contact, regional history, shared environments.

This is related to Galton’s Problem: apparent similarity may reflect shared history rather than independent evolution.

Colouring or faceting by family can reveal dependence; it does not correct it. Formal evolutionary claims require structure-aware models beyond Assignment 2.

21. Assignment 2 Connection

The revised assignment follows this sequence:

  1. Inspect — unit, variables, missingness.
  2. Visualize the evidence — family or macroarea representation.
  3. Visualize diversity — kin_term_count histogram and bin-width sensitivity.
  4. Compare — one purposeful grouped or faceted display.
  5. Consider dependence — phylogenetic and/or spatial autocorrelation.
  6. Interpret responsibly — what the graphs show, one question worth investigating, and one conclusion they do not justify.

No hypothesis tests, p-values, confidence intervals, phylogenetic models, or spatial autocorrelation tests are required.

22. Practical ggplot2 Checklist

Before accepting a graph, ask:

  • Data: What is one row? What dataset is plotted? Is missingness relevant?
  • Mapping: Which variables are mapped to x, y, colour, shape, or size?
  • Geom/stat: What marks are drawn? Does the geom compute first?
  • Comparison: What comparison should the reader make? Would ordering, facets, or raw points help?
  • Scale/design: Does the visual channel match the measurement scale? Are axes and legends readable?
  • Interpretation: What does the graph show in this sample? What does it hide? What does it not justify?

23. Practice Progression: What You Should Be Able to Do Without Copying

Use this as a self-check before beginning Assignment 2.

Level 1 — Read

Given a ggplot2 command, identify:

  • the dataset;
  • the variables mapped inside aes();
  • the geom;
  • fixed aesthetic settings;
  • labels and theme.

Level 2 — Modify

Given a working graph, change one purposeful element:

  • reorder categories;
  • change histogram bin width;
  • add raw observations to a boxplot;
  • change from one-panel grouping to facets;
  • improve labels.

Level 3 — Construct

Given a question and variables, choose and construct an appropriate graph without being told the geom.

Example:

“Are languages evenly represented across macroareas?”

You should recognize this as a categorical frequency question and choose a bar chart.

Level 4 — Interpret

Explain:

  • what the graph shows in the observed sample;
  • what graphical choices influence the display;
  • what the graph may hide;
  • what question it suggests next; and
  • what inferential conclusion it does not establish.

Assignment 2 mainly assesses Levels 3 and 4. The earlier practices are designed to get you there.

24. Practice Challenges

A. Mapping or setting? Predict the result before running:

geom_point(aes(colour = macroarea))
geom_point(colour = "steelblue")
geom_point(aes(colour = "steelblue"))

B. Count or column? Explain why geom_bar() and geom_col() require different data structures.

C. Bin-width sensitivity. Make three histograms of the same variable. Identify one stable feature and one bin-sensitive feature.

D. Summary versus observations. Compare a boxplot alone with boxplot + jitter. What becomes visible?

E. Fixed versus free facets. Which better supports between-group comparison?

F. Description versus inference. Rewrite “Macroarea causes differences in kinship complexity” as a defensible descriptive statement.

G. Evidence structure. Explain why a bar chart of sample composition is analytically relevant even though it does not visualize the substantive outcome.

25. Reading Guide

ggplot2: Elegant Graphics for Data Analysis, 3e

Use the current online third edition as the deep reference for ggplot2’s grammar and mechanics. Prioritize the introduction/grammar, first steps, layers, scales and guides, coordinate systems, and faceting. It is especially useful for understanding why ggplot2 behaves as it does rather than merely copying recipes.

Healy, Data Visualization: A Practical Introduction

Use Healy as the social-science visualization companion. Focus on clear graphical construction, substantive comparison, perception, and communication. It is especially useful for moving from code that produces a plot to a graph that helps a reader see the intended evidence.

R for Data Science, 2e

Use R4DS for the practical EDA workflow and beginner-friendly ggplot2 practice, especially Data visualization, Layers, Exploratory data analysis, and Communication. Its EDA framework emphasizes generating questions, seeking answers through visualization/transformation/modeling, and refining the questions.

26. Core Takeaways

  • EDA is a mode of inquiry, not a chart checklist.
  • Visualization is statistical reasoning, not decoration.
  • Choose graphics from variable structure and analytical purpose.
  • A ggplot is built from data, mappings, layers, scales, coordinates, facets, and themes.
  • Variable inside aes(); fixed appearance outside aes().
  • Geoms may compute statistical transformations before drawing.
  • Comparison must be designed.
  • Faceting asks whether patterns hold under different conditions.
  • Visualize the structure of the evidence before substantive interpretation.
  • Description is not inference.
  • Cross-cultural observations may be spatially and phylogenetically dependent.
  • EDA can reveal dependence; it does not automatically correct it.
  • A good EDA ends with a better next question.
