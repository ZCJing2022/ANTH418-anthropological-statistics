How to use this workbook

Week 2 established the computational environment. Week 3 asks a more fundamental question: What do our variables mean, how were they measured, and what can the design legitimately support?

concept → definition → operationalization → variable → measurement → design → inference

Learning objectives

By the end, you should be able to distinguish concepts, definitions, variables, and values; classify levels of measurement; distinguish reliability, precision, accuracy, and validity; identify units of analysis; classify research designs; state conditions for causal inference; and translate a question into a transparent research plan.

Part I — From concepts to empirical values

1. Variables become evidence

Social research moves from:

abstract concept → conceptual definition → operational definition → empirical values

A variable is not the idea itself. It is an empirical property that can take different values or categories. The operational definition is the recipe that makes data generation visible.

Practice 1

Choose an anthropological or archaeological concept.

  • Abstract concept: __________________
  • Conceptual definition: ______________
  • Operational definition: ______________
  • Variable: ___________________________
  • Possible values: ____________________

What could go wrong if the operational definition captures only part of the concept?

Part II — Variable roles and theory

3. Independent/predictor and dependent/outcome variables

Theory assigns roles. In experiments, X may be manipulated; in observational research, variation in X is measured in relation to Y.

Practice 2

Identify X and Y:

  1. Does distance from a raw-material source predict the proportion of local stone?
  2. Do human nitrogen-isotope values differ between archaeological sites?
  3. Does household wealth predict dietary diversity?

Then explain why the same variable could have a different role in another question.

Part V — Measurement quality

7. Reliability, precision, accuracy, validity

  • Reliability: consistent/repeatable.
  • Precision: fine resolution.
  • Accuracy: low systematic bias.
  • Validity: measures the intended concept.
measurement_demo <- tibble(
  trial = 1:6,
  instrument_A = c(10.0, 10.1, 9.9, 10.0, 10.1, 9.9),
  instrument_B = c(12.0, 12.1, 11.9, 12.0, 12.1, 11.9),
  target = 10
)

measurement_demo |>
  summarise(
    sd_A = sd(instrument_A),
    bias_A = mean(instrument_A - target),
    sd_B = sd(instrument_B),
    bias_B = mean(instrument_B - target)
  )
# A tibble: 1 × 4
    sd_A bias_A   sd_B bias_B
   <dbl>  <dbl>  <dbl>  <dbl>
1 0.0894      0 0.0894      2

Which instrument is reliable? Which is accurate? Why can tightly clustered readings still be wrong?

8. Reliability and validity are not the same

Week 3 discusses reliability through interobserver/intercoder, test-retest, parallel-form, and internal consistency, and validity through face, content, construct, and criterion evidence.

Practice 4

Two archaeologists classify the same 100 sherds identically 98% of the time.

  1. What quality does this directly address?
  2. Does it prove that the typology captures the intended historical phenomenon?
  3. What validity question remains?

  1. What does one row represent?

Part XIV — Conceptual debugging

19. Diagnose the mistake

For each, identify the problem:

  1. Averaging arbitrary numeric codes for artifact types.
  2. Treating repeated measurements from one individual as independent people.
  3. Claiming causation from an observational correlation alone.
  4. Using a highly repeatable instrument that measures the wrong construct.
  5. Collecting age only as broad categories when exact age was available.
  6. Inferring individual behavior from a group-level association.

Part XV — Integrated practice

20. Mini research-design challenge

Using the Knipper teaching data:

  1. Formulate one answerable research question.
  2. Identify the unit of analysis.
  3. Classify the variables and measurement levels.
  4. State how each key variable is operationalized.
  5. Inspect missingness and data structure.
  6. Identify predictor/outcome roles if appropriate.
  7. Classify the design.
  8. State at least two validity or inference limitations.
  9. Write a short Research Design section in prose.
  10. Include the R code used to audit the data.
  11. Render the document.

Part XVI — Mastery checklist

Final challenge — explain the chain without code

In plain English, explain:

concept → definition → operationalization → variable → measurement → unit of analysis → design → evidence → inference

If you can explain why each link matters, rather than merely name it, you have mastered the central Week 3 logic.

Clean Render Test

  1. Save the QMD.
  2. Choose Session → Restart R.
  3. Do not recreate objects manually in the Console.
  4. Render the complete document.
  5. If it fails, identify what the document assumed but never created.

A successful clean render shows that your research-design audit is computationally self-contained.
